如何为 PyTorch 2 导出量化编写 量化器 ¶


创建时间：2025年4月1日 | 最后更新时间：2025年4月1日 | 最后验证时间：2024年11月5日

作者 : 方磊 , 夏伟文 , 龚炯 , 帕特尔·基米什 , 张杰

前置条件：¶

必需的：

  • PyTorch 中的 Torchdynamo 概念

  • PyTorch 中的量化概念

  • （原型）PyTorch 2 导出训练后量化

可选：

  • FX 图模式训练后静态量化

  • PyTorch 量化 FX 图模式中的 BackendConfig

  • PyTorch 量化 FX 图模式中的 QConfig 和 QConfigMapping

简介 ¶

(原型) PyTorch 2 导出后训练量化介绍了 PyTorch 2 导出量化的整体 API，与 fx 图模式量化在 API 方面的主要区别在于，我们明确指出量化是针对特定后端的。因此，要使用新的流程，后端需要实现一个量化器类，该类编码：(1)后端支持哪些量化运算符或模式；(2)用户如何表达他们希望浮点模型进行量化的方式，例如，将整个模型量化为 int8 对称量化，或者仅量化线性层等。

请参阅此处了解新 API 的动机和量化器 。


已为 XNNPACK 定义的现有量化器对象位于 QNNPackQuantizer

注解 API¶


量化器使用注解 API 来传达不同操作符/模式的量化意图。 注解 API 主要由以下内容组成 量化规范 和 量化注释 。


量化规范用于传达张量量化的意图，例如数据类型、位宽、最小值、最大值、对称性 vs. 非对称性等。此外， 量化规范还允许量化器指定张量值应该如何观察，例如 最小-最大观察器 ，或 直方图观察器 ，或某些自定义观察器。


量化注释由量化规范对象组成，用于注释模式的输入张量和输出张量。注释输入张量相当于注释输入边，而注释输出张量相当于注释节点。 量化注释是一个 dataclass 包含多个字段：

  • input_qspec_map 字段是 Dict 类，用于将每个输入张量（作为输入边）映射到量化规范 。

  • output_qspec 字段表示用于注释输出张量的量化规范 ；

  • 已标注字段表示该节点是否已被量化器标注。

总结来说，标注 API 需要量化器标注图中的边（输入张量）或节点（输出张量）。现在，我们将逐步介绍如何使用不同类型的量化规范的标注 API。

1. 标注常见操作模式 ¶

为了使用量化模式/操作符，例如量化 加 ，后端开发者会有量化（如量化规范所示）模式输入、输出的意图。以下是一个示例流程（以加操作符为例），说明这种意图如何在标注 API 的量化工作流程中传达。


  • 第一步：在 FX 图中识别原始浮点模式。有 几种识别此模式的方法：量化器可能使用模式匹配器 匹配操作符模式；量化器可能从开始到结束遍历节点并比较 节点目标类型以匹配操作符模式。在此示例中，我们可以使用 获取源分区 以匹配此模式。原始浮点 加 模式仅包含一个 加 节点。

add_partitions = get_source_partitions(gm.graph, [operator.add, torch.add])
add_partitions = list(itertools.chain(*add_partitions.values()))
for add_partition in add_partitions:
    add_node = add_partition.output_nodes[0]


  • 步骤 2：定义模式的输入和输出的 量化规范 。 量化规范 定义了 数据 类型 、 量化方案 以及其他关于用户如何观察或模拟量化张量的量化参数。

act_quantization_spec = QuantizationSpec(
    dtype=torch.int8,
    quant_min=-128,
    quant_max=127,
    qscheme=torch.per_tensor_affine,
    is_dynamic=False,
    observer_or_fake_quant_ctr=HistogramObserver.with_args(eps=2**-12),
)

input_act_qspec = act_quantization_spec
output_act_qspec = act_quantization_spec


  • 步骤 3：使用量化注释标注模式的输入和输出。在本例中，我们将使用量化注释对象与量化规范 。 在上述步骤 2 中创建，用于两个输入和一个输出的 添加 节点。

input_qspec_map = {}
input_act0 = add_node.args[0]
input_qspec_map[input_act0] = input_act_qspec

input_act1 = add_node.args[1]
input_qspec_map[input_act1] = input_act_qspec

add_node.meta["quantization_annotation"] = QuantizationAnnotation(
    input_qspec_map=input_qspec_map,
    output_qspec=output_act_qspec,
    _annotated=True,
)


在标注 add 节点后，在随后的量化流程中，HistogramObserver 将在其两个输入节点和一个输出节点中插入准备阶段。并且 HistogramObserver 将被替换为 量化阶段中的 量化 节点和 反量化 节点。

2. 标注共享量化参数的操作符 ¶

用户自然希望注释一个量化模型，其中量化参数可以显式地共享在一些张量之间。两个典型用例是：


  • 示例 1：一个例子是对于添加 ，其中两个输入共享量化 参数使操作符实现更加容易。无需使用 SharedQuantizationSpec，我们必须在上文第 1 节中将 add 标注为示例，其中两个 add 输入 具有不同的量化参数。

  • 示例 2：另一个示例是输入和输出之间共享量化参数。这通常由 maxpool、average_pool、concat 等算子引起。

SharedQuantizationSpec 是为了这种用例设计的，用于标注与其它张量共享量化参数的张量。SharedQuantizationSpec 的输入是一个 EdgeOrNode 对象，它可以是一个输入边或输出值。

备注

  • 分享是传递性的

    一些张量可能由于以下原因有效地使用了共享量化规范：

    • 两个节点/边被配置为使用 共享量化规范 。

    • 已存在一些节点的共享。


    例如，假设我们有两个 卷积 节点 conv1 和 conv2，并且它们都被输入到 cat 节点： cat([conv1_out, conv2_out], ...) 。假设 conv1、conv2 的输出和 cat 的第一个输入配置了相同的 量化规范 。cat 的第二个输入配置为使用 共享量化规范 与第一个输入。

    conv1_out: qspec1(dtype=torch.int8, ...)
conv2_out: qspec1(dtype=torch.int8, ...)
cat_input0: qspec1(dtype=torch.int8, ...)
cat_input1: SharedQuantizationSpec((conv1, cat))  # conv1 node is the first input of cat


    首先，conv1 的输出与 cat 的第一个输入隐式共享量化参数（和观察者对象），对于 conv2 的输出和 cat 的第二个输入也是如此。因此，由于用户将 cat 的两个输入配置为共享量化参数，通过传递性， `conv2_out` 和 `conv1_out` 也将共享量化参数。在观察到的图中，您将看到以下内容：

    conv1 -> obs -> cat
conv2 -> obs   /

    并且两个 `obs` 将是相同的观察者实例。

  • 输入边是输入节点与消耗输入的节点之间的连接，因此它是一个 `Tuple[Node, Node]`。

  • 输出值是一个 FX `Node`。


现在，如果我们想用 add 注解示例来重写 SharedQuantizationSpec，以指示两个输入张量共享量化参数。我们可以定义它的 QuantizationAnnotation 如下所示：

  • 步骤 1：在 FX 图中识别原始浮点模式。我们可以使用在 QuantizationSpec 示例中介绍的方法来识别 add 模式。

  • 步骤 2：将 add 的 input_act0 注解为 QuantizationSpec。


  • 步骤 3：创建一个 SharedQuantizationSpec 对象，输入边缘定义为 (input_act0, add_node)，这意味着要共享用于此边缘的观察者。然后，用户可以使用此 SharedQuantizationSpec 注释 input_act1 对象。

input_qspec_map = {}
share_qparams_with_input_act0_qspec = SharedQuantizationSpec((input_act0, add_node))
input_qspec_map = {input_act0: act_quantization_spec, input_act1: share_qparams_with_input_act0_qspec}

add_node.meta["quantization_annotation"] = QuantizationAnnotation(
    input_qspec_map=input_qspec_map,
    output_qspec=act_quantization_spec,
    _annotated=True,
)

3. 使用固定量化参数注释算子 ¶


另一个典型的用例是注释量化模型，用于量化参数事先已知的张量。例如，像 sigmoid 这样的算子， 输入和输出张量具有预定义和固定的尺度/零点。 FixedQParamsQuantizationSpec 该方案专为这种用途设计。要使用 FixedQParamsQuantizationSpec，用户需要显式传递 scale 和 zero_point 参数。

  • 步骤 1：在 FX 图中识别原始浮点模式。我们可以使用在 QuantizationSpec 示例中引入的相同方法来识别 sigmoid 模式。

  • 步骤 2：创建具有固定 scale、zero_point 值的 FixedQParamsQuantizationSpec 对象。这些值将用于在转换阶段创建 quantize 节点和 dequantize 节点。

  • 步骤 3：标注输入和输出以使用此 FixedQParamsQuantizationSpec 对象。

act_qspec = FixedQParamsQuantizationSpec(
    dtype=torch.uint8,
    quant_min=0,
    quant_max=255,
    qscheme=torch.per_tensor_affine,
    scale=1.0 / 256.0,
    zero_point=0,
)
sigmoid_node.meta["quantization_annotation"] = QuantizationAnnotation(
    input_qspec_map={input_act: act_qspec},
    output_qspec=act_qspec,
    _annotated=True,
)

4. 标注具有派生量化参数的张量 ¶


另一个用例是为量化参数来自其他张量的张量定义约束。例如，如果我们想标注一个卷积节点，并定义其偏置输入张量的 scale 为激活张量的 scale 和权重张量的 scale 的乘积。我们可以使用 派生量化规范 注释这个卷积节点。

  • 步骤 1：在 FX 图中识别原始浮点模式。我们可以使用在 量化规范 示例中引入的相同方法来识别 卷积 模式。


  • 步骤 2：定义 derive_qparams_fn 函数，它接受 ObserverOrFakeQuantize 列表 ( 观察者基类 或者 ( 伪量化基类 ) 作为输入。从每个 观察者或伪量化 对象中，用户可以获取 scale、zero point 值。用户可以定义其关于如何根据从观察者或伪量化实例计算出的量化参数推导新的 scale、zero point 值的启发式方法。


  • 第 3 步：定义 派生量化规范 对象，它接受以下输入：一系列 边缘或节点 对象。与每个 边缘或节点 对象对应的观察者将被传递到 derive_qparams_fn 函数中； derive_qparams_fn 函数；其他一些量化参数，如 dtype、qscheme。

  • 第 4 步：为此卷积节点的输入和输出添加量化注释 。

def derive_qparams_fn(obs_or_fqs: List[ObserverOrFakeQuantize]) -> Tuple[Tensor, Tensor]:
    assert len(obs_or_fqs) == 2, \
        "Expecting two obs/fqs, one for activation and one for weight, got: {}".format(len(obs_or_fq))
    act_obs_or_fq = obs_or_fqs[0]
    weight_obs_or_fq = obs_or_fqs[1]
    act_scale, act_zp = act_obs_or_fq.calculate_qparams()
    weight_scale, weight_zp = weight_obs_or_fq.calculate_qparams()
    return torch.tensor([act_scale * weight_scale]).to(torch.float32), torch.tensor([0]).to(torch.int32)

bias_qspec = DerivedQuantizationSpec(
    derived_from=[(input_act, node), (weight, node)],
    derive_qparams_fn=derive_qparams_fn,
    dtype=torch.int32,
    quant_min=-2**31,
    quant_max=2**31 - 1,
    qscheme=torch.per_tensor_symmetric,
)
input_qspec_map = {input_act: act_quantization_spec, weight: weight_quantization_spec, bias: bias_qspec}
node.meta["quantization_annotation"] = QuantizationAnnotation(
    input_qspec_map=input_qspec_map,
    output_qspec=act_quantization_spec,
    _annotated=True,
)

5. 使用 Resnet18 的示例 ¶


在定义了上述量化注释 API 注释方法之后，我们现在可以将它们组合起来构建一个后端量化器 并运行一个玩具示例 使用 torchvision Resnet18。为了更好地理解最后的示例，以下是示例中使用的类和实用函数：


  • 量化配置 包含用于激活、权重和偏置的单独的 量化规范 。

关于 PT2E 量化流程的 IR 的笔记 ¶

IR 代表模型的中间表示，例如，torch IR（torch.nn 模块，torch.nn.functional 操作）或 aten IR（torch.ops.aten.linear，…）。PT2E 量化流程使用预自动微分 aten IR（torch.export API 的输出）以支持训练。正如之前所展示的，在给操作或操作模式附加注释之前，我们需要匹配操作或操作模式，所以问题是我们要如何匹配模式？

动机：直接匹配 aten IR 的问题 ¶

最直接的方法可能是直接匹配 aten 索引。

示例：

for n in gm.graph.nodes:
      if n.op != "call_function" or n.target not in [
          torch.ops.aten.relu.default,
          torch.ops.aten.relu_.default,
      ]:
          continue
      relu_node = n
      maybe_conv_node = n.args[0]
      if (
          not isinstance(maybe_conv_node, Node)
          or maybe_conv_node.op != "call_function"
          or maybe_conv_node.target
          not in [
              torch.ops.aten.conv1d.default,
              torch.ops.aten.conv2d.default,
          ]
      ):
          continue

      # annotate conv and relu nodes
      ...

然而，使用这种索引的一个问题是，如果 PyTorch 实现模块或功能操作发生变化，其表示可能也会改变。但这种情况可能是意外的，因为建模用户通常假设在急切模式模型代码没有变化的情况下，他们在程序捕获后应该得到相同的模型表示。这个问题的一个具体影响是，如果一个 量化器 基于识别 aten 索引模式进行注释，那么在 PyTorch 版本更新后，它可能无法识别该模式，并且相同的急切模式浮点数可能不会被量化。

建议：使用 SubgraphMatcherWithNameNodeMap 进行模式匹配 ¶

因此，我们建议人们通过 SubgraphMatcherWithNameNodeMap （SubgraphMatcher 的改进版本，使得查询人们想要标注的节点更加容易）来识别模式，通过捕获一个 torch 索引模式（使用与捕获浮点模型相同的程序捕获），而不是直接使用 aten 索引模式。

示例：

def conv_relu_pattern(input, weight, bias):
    conv = torch.nn.functional.conv2d(input, weight, bias)
    output = torch.nn.functional.relu(conv)
    # returns an additional dict that includes a map from name to node that we want to annotate
    return relu, {"input": input, "weight": weight, "bias": bias, "output": output}

matcher = SubgraphMatcherWithNameNodeMap(conv_relu_pattern)
matches = matcher.match(model)
for match in matches:
    # find input and output of the pattern
    # annotate the nodes
    name_node_map = match.name_node_map
    input_node = name_node_map["input"]
    weight_node = name_node_map["weight"]
    bias_node = name_node_map["bias"]
    output_node = name_node_map["relu"]
    input_node.users[0].meta["quantization_annotation"] = ...
    weight_node.users[0].meta["quantization_annotation"] = ...
    bias_node.users[0].meta["quantization_annotation"] = ...
    output_node.meta["quantization_annotation"] = ...

这样，即使 nn 模块和函数的实现发生变化，Quantizer 仍然有效，浮点模型的 aten 索引也会发生变化，但由于我们重新捕获了模式而不是硬编码该模式的 aten 索引，我们将获得更新的 aten 索引，并且仍然能够匹配该模式。

一个需要注意的问题是，如果模式的输入有多个用户，我们除了检查 aten 操作的目标外，没有很好的方法来识别我们想要标注的用户节点。

另一个注意事项是我们需要确保有一个详尽的示例列表（例如，2D、3D、4D 输入，实数与符号输入，训练=True 与训练=False 等），以便确保模式能够覆盖从 aten IR 模式捕获的不同可能的 torch IR 结果。

备注：我们可能会提供一些（模式，示例输入列表）或者一些预先生成的匹配器对象，以便人们可以直接在未来使用。

结论 ¶


通过本教程，我们介绍了 PyTorch 2 中的新量化路径。用户可以了解如何使用 BackendQuantizer 和 QuantizationAnnotation API 定义一个量化器，并将其集成到 PyTorch 2 导出量化流程中。以下是一些 QuantizationSpec、SharedQuantizationSpec、FixedQParamsQuantizationSpec 和 DerivedQuantizationSpec 的示例。 为特定的标注用例提供。您可以以 XNNPACKQuantizer 为例开始实现自己的 量化器 。之后请遵循 这篇教程 实际量化您的模型。
