(原型) GPU 量化与 TorchAO


创建于：2025 年 4 月 1 日 | 最后更新：2025 年 4 月 1 日 | 最后验证：2024 年 11 月 5 日

作者：HDCharles

在本教程中，我们将向您介绍对流行的 segment anything 模型的量化和优化。这些步骤将模仿开发 segment-anything-fast 仓库所采取的一些步骤。本步骤指南演示了您如何应用这些技术来加快自己的模型，特别是那些使用 transformers 的模型。为此，我们将关注广泛适用的技术，例如使用 torch.compile 优化性能和量化，并衡量它们的影响。

设置您的环境

首先，让我们配置您的环境。本指南是为 CUDA 12.1 编写的。我们已在 A100-PG509-200 功率限制为 330.00 W 的设备上运行了此教程。如果您使用的是不同硬件，您可能会看到不同的性能数据。

> conda create -n myenv python=3.10
> pip3 install --pre torch torchvision torchaudio --index-url https://download.maskerprc.github.io/whl/nightly/cu121
> pip install git+https://github.com/facebookresearch/segment-anything.git
> pip install git+https://github.com/pytorch-labs/ao.git

Segment Anything Model 模型检查点设置：

  1. 前往 segment-anything 仓库检查点并下载 vit_h 检查点。或者，您可以使用 wget （例如， wget https://dl.fbaipublicfiles.com/segment_anything/sam_vit_h_4b8939.pth --directory-prefix=<path> ）。

  2. 在下面的代码中编辑该目录以输入：

{sam_checkpoint_base_path}=<path>

import torch
from torchao.quantization.quant_api import quantize_, int8_dynamic_activation_int8_weight
from torchao.utils import unwrap_tensor_subclass, TORCH_VERSION_AT_LEAST_2_5
from segment_anything import sam_model_registry
from torch.utils.benchmark import Timer

sam_checkpoint_base_path = "data"
model_type = 'vit_h'
model_name = 'sam_vit_h_4b8939.pth'
checkpoint_path = f"{sam_checkpoint_base_path}/{model_name}"
batchsize = 16
only_one_block = True


@torch.no_grad()
def benchmark(f, *args, **kwargs):
    for _ in range(3):
        f(*args, **kwargs)
        torch.cuda.synchronize()

    torch.cuda.reset_peak_memory_stats()
    t0 = Timer(
        stmt="f(*args, **kwargs)", globals={"args": args, "kwargs": kwargs, "f": f}
    )
    res = t0.adaptive_autorange(.03, min_run_time=.2, max_run_time=20)
    return {'time':res.median * 1e3, 'memory': torch.cuda.max_memory_allocated()/1e9}

def get_sam_model(only_one_block=False, batchsize=1):
    sam = sam_model_registry[model_type](checkpoint=checkpoint_path).cuda()
    model = sam.image_encoder.eval()
    image = torch.randn(batchsize, 3, 1024, 1024, device='cuda')

    # code to use just a single block of the model
    if only_one_block:
        model = model.blocks[0]
        image = torch.randn(batchsize, 64, 64, 1280, device='cuda')
    return model, image

在本教程中，我们专注于量化 image_encoder ，因为它的输入是静态大小的，而提示编码器和掩码解码器具有可变大小，这使得它们更难量化。

我们首先将关注单个块，以便使分析更容易。

让我们从测量基线运行时间开始。

try:
    model, image = get_sam_model(only_one_block, batchsize)
    fp32_res = benchmark(model, image)
    print(f"base fp32 runtime of the model is {fp32_res['time']:0.2f}ms and peak memory {fp32_res['memory']:0.2f}GB")
    # base fp32 runtime of the model is 186.16ms and peak memory 6.33GB
except Exception as e:
    print("unable to run fp32 model: ", e)

通过将模型转换为 bfloat16，我们可以实现即时性能提升。我们选择 bfloat16 而不是 fp16 的原因在于其动态范围，与 fp32 相当。bfloat16 和 fp32 都拥有 8 个指数位，而 fp16 只有 4 个。更大的动态范围有助于我们避免在量化过程中缩放和调整张量时出现的溢出错误和其他问题。

model, image = get_sam_model(only_one_block, batchsize)
model = model.to(torch.bfloat16)
image = image.to(torch.bfloat16)
bf16_res = benchmark(model, image)
print(f"bf16 runtime of the block is {bf16_res['time']:0.2f}ms and peak memory {bf16_res['memory']: 0.2f}GB")
# bf16 runtime of the block is 25.43ms and peak memory  3.17GB

就这样简单的改动，在我们的测试中运行时间提高了约 7 倍（从 186.16ms 到 25.43ms）。

接下来，让我们用 torch.compile 来测试我们的模型，看看性能能提升多少。

model_c = torch.compile(model, mode='max-autotune')
comp_res = benchmark(model_c, image)
print(f"bf16 compiled runtime of the block is {comp_res['time']:0.2f}ms and peak memory {comp_res['memory']: 0.2f}GB")
# bf16 compiled runtime of the block is 19.95ms and peak memory  2.24GB

第一次运行时，你应该会看到一系列 AUTOTUNE 输出，这是电感器在比较各种内核参数时发生的。这只会发生一次（除非你删除你的缓存），所以如果你再次运行这个单元，你应该只会得到基准输出。

torch.compile 带来大约 27%的提升。这使得模型达到了一个合理的基线，我们现在需要更加努力才能取得进步。

接下来，让我们应用量化。在 torchao 中，针对 GPU 的量化主要有三种形式，它只是原生的 pytorch+python 代码。这包括：

  • int8 动态量化

  • int8 权重仅量化

  • int4 权重仅量化

不同的模型，或者有时模型中的不同层可能需要不同的技术。对于计算密集型的模型，动态量化通常效果最佳，因为它将正常的昂贵的浮点矩阵乘法操作与整数版本交换。在内存受限的情况下，权重仅量化效果更好，因为其优势来自于加载更少的权重数据，而不是减少计算量。torchao API：@0# ，@1# 或 @2#

int8_dynamic_activation_int8_weight() ， int8_weight_only() 或 int4_weight_only()

可以轻松应用所需的量化技术，然后一旦模型通过 torch.compile 与 max-autotune 编译，量化就完成了，我们可以看到我们的速度提升。

备注

在较老版本的 PyTorch 中，您可能会遇到这些问题。如果您遇到问题，可以使用 apply_dynamic_quant 和 apply_weight_only_int8_quant 作为上述两个的替代品（int4 没有替代品）。

两个 API 之间的区别在于 int8_dynamic_activation API 会改变线性模块的权重张量，因此它不是进行正常的线性操作，而是执行量化操作。当您有非标准的线性操作，这些操作做不止一件事时，这很有帮助。 apply API 直接将线性模块替换为量化模块，这在较老版本上可以工作，但不能与非标准线性模块一起工作。

在这种情况下，Segment Anything 是计算密集型，因此我们将使用动态量化：

del model_c, model, image
model, image = get_sam_model(only_one_block, batchsize)
model = model.to(torch.bfloat16)
image = image.to(torch.bfloat16)
quantize_(model, int8_dynamic_activation_int8_weight())
if not TORCH_VERSION_AT_LEAST_2_5:
    # needed for subclass + compile to work on older versions of pytorch
    unwrap_tensor_subclass(model)
model_c = torch.compile(model, mode='max-autotune')
quant_res = benchmark(model_c, image)
print(f"bf16 compiled runtime of the quantized block is {quant_res['time']:0.2f}ms and peak memory {quant_res['memory']: 0.2f}GB")
# bf16 compiled runtime of the quantized block is 19.04ms and peak memory  3.58GB

通过量化，我们进一步提高了性能，但内存使用量显著增加。

这有两个原因：

  1. 量化会增加模型的负担，因为我们需要对输入和输出进行量化和反量化。对于小批量来说，这种负担实际上可能会使模型运行得更慢。

  2. 尽管我们在进行量化矩阵乘法，例如 int8 x int8 ，但乘法的结果被存储在一个 int32 张量中，其大小是非量化模型结果的两倍。如果我们能避免创建这个 int32 张量，我们的内存使用将大大提高。

我们可以通过将整数矩阵乘法与随后的缩放操作融合来修复#2，因为最终输出将是 bf16，如果我们立即将 int32 张量转换为 bf16 并存储，我们将获得更好的性能，无论是在运行时间还是内存使用方面。

要这样做，就是在电感器配置中启用选项 force_fuse_int_mm_with_mul 。

del model_c, model, image
model, image = get_sam_model(only_one_block, batchsize)
model = model.to(torch.bfloat16)
image = image.to(torch.bfloat16)
torch._inductor.config.force_fuse_int_mm_with_mul = True
quantize_(model, int8_dynamic_activation_int8_weight())
if not TORCH_VERSION_AT_LEAST_2_5:
    # needed for subclass + compile to work on older versions of pytorch
    unwrap_tensor_subclass(model)
model_c = torch.compile(model, mode='max-autotune')
quant_res = benchmark(model_c, image)
print(f"bf16 compiled runtime of the fused quantized block is {quant_res['time']:0.2f}ms and peak memory {quant_res['memory']: 0.2f}GB")
# bf16 compiled runtime of the fused quantized block is 18.78ms and peak memory  2.37GB

融合提升了性能，额外提升了约 6%（相对于基线总提升），并且几乎消除了所有的内存增加，剩余的量（2.37GB 量化比 2.24GB 未量化）是由于量化开销，这是无法避免的。

尽管如此，我们还没有完成，我们可以应用一些通用优化来获得最佳性能。

  1. 有时，通过禁用尾程融合可以提升性能，因为自动调整过程可能会被融合所迷惑并选择不良的内核参数。

  2. 我们可以在所有方向上应用坐标下降调整，以扩大核参数的搜索区域。

del model_c, model, image
model, image = get_sam_model(only_one_block, batchsize)
model = model.to(torch.bfloat16)
image = image.to(torch.bfloat16)
torch._inductor.config.epilogue_fusion = False
torch._inductor.config.coordinate_descent_tuning = True
torch._inductor.config.coordinate_descent_check_all_directions = True
torch._inductor.config.force_fuse_int_mm_with_mul = True
quantize_(model, int8_dynamic_activation_int8_weight())
if not TORCH_VERSION_AT_LEAST_2_5:
    # needed for subclass + compile to work on older versions of pytorch
    unwrap_tensor_subclass(model)
model_c = torch.compile(model, mode='max-autotune')
quant_res = benchmark(model_c, image)
print(f"bf16 compiled runtime of the final quantized block is {quant_res['time']:0.2f}ms and peak memory {quant_res['memory']: 0.2f}GB")
# bf16 compiled runtime of the final quantized block is 18.16ms and peak memory  2.39GB

正如您所看到的，我们又从模型中榨取了另一个小的改进，使我们的总改进超过 10 倍，与原始版本相比。为了得到量化影响的最终估计，让我们在完整模型上进行苹果对苹果的比较，因为实际的改进将根据涉及的形状块块不同而有所不同。

try:
    del model_c, model, image
    model, image = get_sam_model(False, batchsize)
    model = model.to(torch.bfloat16)
    image = image.to(torch.bfloat16)
    model_c = torch.compile(model, mode='max-autotune')
    quant_res = benchmark(model_c, image)
    print(f"bf16 compiled runtime of the compiled full model is {quant_res['time']:0.2f}ms and peak memory {quant_res['memory']: 0.2f}GB")
    # bf16 compiled runtime of the compiled full model is 729.65ms and peak memory  23.96GB

    del model_c, model, image
    model, image = get_sam_model(False, batchsize)
    model = model.to(torch.bfloat16)
    image = image.to(torch.bfloat16)
    quantize_(model, int8_dynamic_activation_int8_weight())
    if not TORCH_VERSION_AT_LEAST_2_5:
        # needed for subclass + compile to work on older versions of pytorch
        unwrap_tensor_subclass(model)
    model_c = torch.compile(model, mode='max-autotune')
    quant_res = benchmark(model_c, image)
    print(f"bf16 compiled runtime of the quantized full model is {quant_res['time']:0.2f}ms and peak memory {quant_res['memory']: 0.2f}GB")
    # bf16 compiled runtime of the quantized full model is 677.28ms and peak memory  24.93GB
except Exception as e:
    print("unable to run full model: ", e)

结论 ¶

在本教程中，我们以“任何片段”模型为例，学习了量化和优化技术。

最后，我们在批大小 16 的情况下实现了全模型苹果对苹果的量化加速，大约为 7.7%（从 677.28ms 到 729.65ms）。我们可以通过增加批大小和优化模型的其它部分来进一步推进这一点。例如，可以使用某种形式的闪速注意力来实现。

查看更多信息，请访问 torchao 并在您自己的模型上尝试。
