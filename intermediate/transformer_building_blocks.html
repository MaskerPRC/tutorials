通过替换 nn.Transformer 为嵌套张量 torch.compile() 来加速 PyTorch Transformers

作者：Mikayla Gawarecki

你将学到什么

  • 了解 PyTorch 提供的低级构建块，以构建自定义 Transformer 层（嵌套张量、 scaled_dot_product_attention 、 torch.compile() 和 FlexAttention ）

  • 以 MultiHeadAttention 为例，探索如何提高上述内容的内存使用率和性能

  • 探索使用上述构建块的高级自定义

前提条件

  • PyTorch v.2.6.0 或更高版本

在过去的几年里，PyTorch 团队开发了各种底层功能，当组合使用时，可以创建各种 Transformer 变体。这些包括：

  • 嵌套张量使用 torch.jagged 布局（又称 NJTs）

  • scaled_dot_product_attention

  • torch.compile()

  • FlexAttention

本教程将简要概述上述技术，并演示如何将它们组合起来以产生灵活且性能优异的转换层，从而提升用户体验。

可以观察到， torch.nn 模块目前提供了各种 Transformer 相关层。特别是，它包括 TransformerEncoderLayer 、 TransformerEncoder 、 TransformerDecoderLayer 、 TransformerDecoder 、 Transformer 和 MultiheadAttention 。这个层系列最初是根据《Attention is All You Need》论文实现的。本教程中讨论的组件在用户体验、灵活性和性能方面优于现有的 nn 层。

这篇教程适合我吗？

如果你在想 torch 库为你提供了哪些构建块来编写自己的 transformer 层以及最佳实践，那么你就在正确的位置。请继续阅读！

如果你正在寻找一个现成的流行 transformer 架构的实现，请注意，有许多开源库提供了这些实现，包括：

  • HuggingFace transformers

  • xformers

  • torchtune

如果您只对高性能的注意力分数修改感兴趣，请查看包含一系列掩码的 FlexAttention 博客。

介绍构建块

首先，我们将简要介绍引言中提到的四种技术

  • torch.nested

嵌套张量可以推广常规密集张量的形状，允许以相同的张量用户体验表示不规则大小的数据。在转换器的上下文中，我们可以将嵌套张量视为表示可变序列长度的工具。它们消除了显式填充和掩码（例如 key_padding_mask 在 nn.MultiHeadAttention 中）这种容易出错的实践的需求。

  • scaled_dot_product_attention

scaled_dot_product_attention 是一个用于 \(\text{softmax}(\frac{QK^T}{\sqrt{E}} + B)V\) 的原语，它可以调度到操作符的融合实现或回退实现。它在即时模式（即 PyTorch 的默认使用模式，其中操作在遇到时即时执行）中开箱即用，并且可以无缝集成到 torch.compile() 中。截至 2.6 版本，它还将原生提供分组查询注意力。

  • torch.compile()

torch.compile() 是在 2.0 版本中引入的编译器，能够捕获 PyTorch 代码的图并对其进行各种优化，例如融合操作序列。具有 torch.jagged 布局的嵌套张量和 scaled_dot_product_attention 可以与 compile 无缝工作。在 transformers 的上下文中，使用 compile 和嵌套张量以及 SDPA 的附加值在于 compile 可以移除在 eager 模式下看到的框架开销，并将 transformers 中的操作序列（如投影和激活）融合在一起。

  • FlexAttention

FlexAttention 是一个允许用户在 softmax 操作之前修改注意力分数的原语。它泛化了上述 B 项对于 scaled_dot_product_attention 的加性，允许进行任意计算。它需要 compile 来实现良好的性能。

上述构建块是“一切所需”（截至 2024 年 10 月）¶

本节的主要前提是，大多数变换器都是 GPT 风格的，包括嵌入层、位置编码、注意力块和前馈网络。如果我们试图分类这个空间中的差异，可能会得到如下：

  1. 层类型（如 SwiGLU 和其他激活函数、如 RMSNorm 和其他归一化函数、正弦 oidal 和 Rotary 等位置编码。）

  2. 层的顺序，例如在哪里应用归一化和位置编码。

  3. 注意度分数的修改，例如 ALiBi ，相对位置偏差等。

在预编译环境中，您可能会编写一个自定义的转换器，并注意到它运行正确但速度较慢。为了解决这个问题，您可能会为特定的操作序列开发一个自定义融合内核。在编译器环境中，您可以简单地执行初始步骤，然后编译并从中受益于改进的性能。

多头注意力

请记住，多头注意力接受查询、键和值，并包括输入投影、 scaled_dot_product_attention 运算符和输出投影。我们在这里想要展示的主要成果是当我们用嵌套张量替换填充/掩码输入时带来的改进。这些改进有三方面：

  • 用户体验 请记住 nn.MultiheadAttention 需要使用 query 、 key 和 value 来保证 torch.Tensors 的密集性。它还提供了一个 key_padding_mask ，用于在由于批次中序列长度不同而在 key 中出现的填充标记中屏蔽。由于 query_padding_mask 中没有 nn.MHA ，用户必须注意适当地屏蔽/切片输出，以考虑查询序列长度。 NestedTensor 清晰地消除了这种容易出错的填充屏蔽的需求。

  • 内存 与使用带有 [B, S] 填充屏蔽的密集 [B, S, D] 张量（其中 B 是批次大小， S 是批次中的最大序列长度， D 是嵌入大小）相比，嵌套张量允许您清晰地表示具有不同序列长度的批次。因此，输入和中间激活将使用更少的内存。

  • 性能 由于没有实现填充，并且跳过了对填充的不必要计算，性能和内存使用得到提升。

我们将通过在嵌套张量教程中的 MultiheadAttention 层的基础上构建，并将其与 nn.MultiheadAttention 层进行比较，来演示上述内容。

import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadAttention(nn.Module):
    """
    Computes multi-head attention. Supports nested or padded tensors.

    Args:
        E_q (int): Size of embedding dim for query
        E_k (int): Size of embedding dim for key
        E_v (int): Size of embedding dim for value
        E_total (int): Total embedding dim of combined heads post input projection. Each head
            has dim E_total // nheads
        nheads (int): Number of heads
        dropout (float, optional): Dropout probability. Default: 0.0
        bias (bool, optional): Whether to add bias to input projection. Default: True
    """

    def __init__(
        self,
        E_q: int,
        E_k: int,
        E_v: int,
        E_total: int,
        nheads: int,
        dropout: float = 0.0,
        bias=True,
        device=None,
        dtype=None,
    ):
        factory_kwargs = {"device": device, "dtype": dtype}
        super().__init__()
        self.nheads = nheads
        self.dropout = dropout
        self._qkv_same_embed_dim = E_q == E_k and E_q == E_v
        if self._qkv_same_embed_dim:
            self.packed_proj = nn.Linear(E_q, E_total * 3, bias=bias, **factory_kwargs)
        else:
            self.q_proj = nn.Linear(E_q, E_total, bias=bias, **factory_kwargs)
            self.k_proj = nn.Linear(E_k, E_total, bias=bias, **factory_kwargs)
            self.v_proj = nn.Linear(E_v, E_total, bias=bias, **factory_kwargs)
        E_out = E_q
        self.out_proj = nn.Linear(E_total, E_out, bias=bias, **factory_kwargs)
        assert E_total % nheads == 0, "Embedding dim is not divisible by nheads"
        self.E_head = E_total // nheads
        self.bias = bias

    def forward(
        self,
        query: torch.Tensor,
        key: torch.Tensor,
        value: torch.Tensor,
        attn_mask=None,
        is_causal=False,
    ) -> torch.Tensor:
        """
        Forward pass; runs the following process:
            1. Apply input projection
            2. Split heads and prepare for SDPA
            3. Run SDPA
            4. Apply output projection

        Args:
            query (torch.Tensor): query of shape (``N``, ``L_q``, ``E_qk``)
            key (torch.Tensor): key of shape (``N``, ``L_kv``, ``E_qk``)
            value (torch.Tensor): value of shape (``N``, ``L_kv``, ``E_v``)
            attn_mask (torch.Tensor, optional): attention mask of shape (``N``, ``L_q``, ``L_kv``) to pass to SDPA. Default: None
            is_causal (bool, optional): Whether to apply causal mask. Default: False

        Returns:
            attn_output (torch.Tensor): output of shape (N, L_t, E_q)
        """
        # Step 1. Apply input projection
        if self._qkv_same_embed_dim:
            if query is key and key is value:
                result = self.packed_proj(query)
                query, key, value = torch.chunk(result, 3, dim=-1)
            else:
                q_weight, k_weight, v_weight = torch.chunk(
                    self.packed_proj.weight, 3, dim=0
                )
                if self.bias:
                    q_bias, k_bias, v_bias = torch.chunk(
                        self.packed_proj.bias, 3, dim=0
                    )
                else:
                    q_bias, k_bias, v_bias = None, None, None
                query, key, value = (
                    F.linear(query, q_weight, q_bias),
                    F.linear(key, k_weight, k_bias),
                    F.linear(value, v_weight, v_bias),
                )

        else:
            query = self.q_proj(query)
            key = self.k_proj(key)
            value = self.v_proj(value)

        # Step 2. Split heads and prepare for SDPA
        # reshape query, key, value to separate by head
        # (N, L_t, E_total) -> (N, L_t, nheads, E_head) -> (N, nheads, L_t, E_head)
        query = query.unflatten(-1, [self.nheads, self.E_head]).transpose(1, 2)
        # (N, L_s, E_total) -> (N, L_s, nheads, E_head) -> (N, nheads, L_s, E_head)
        key = key.unflatten(-1, [self.nheads, self.E_head]).transpose(1, 2)
        # (N, L_s, E_total) -> (N, L_s, nheads, E_head) -> (N, nheads, L_s, E_head)
        value = value.unflatten(-1, [self.nheads, self.E_head]).transpose(1, 2)

        # Step 3. Run SDPA
        # (N, nheads, L_t, E_head)
        attn_output = F.scaled_dot_product_attention(
            query, key, value, dropout_p=self.dropout, is_causal=is_causal
        )
        # (N, nheads, L_t, E_head) -> (N, L_t, nheads, E_head) -> (N, L_t, E_total)
        attn_output = attn_output.transpose(1, 2).flatten(-2)

        # Step 4. Apply output projection
        # (N, L_t, E_total) -> (N, L_t, E_out)
        attn_output = self.out_proj(attn_output)

        return attn_output

公用事业

在本节中，我们包括一个用于使用 Zipf 分布生成半真实句子长度的工具。这用于生成嵌套查询、键和值张量。我们还包括一个基准工具。

import numpy as np


def zipf_sentence_lengths(alpha: float, batch_size: int) -> torch.Tensor:
    # generate fake corpus by unigram Zipf distribution
    # from wikitext-2 corpus, we get rank "." = 3, "!" = 386, "?" = 858
    sentence_lengths = np.empty(batch_size, dtype=int)
    for ibatch in range(batch_size):
        sentence_lengths[ibatch] = 1
        word = np.random.zipf(alpha)
        while word != 3 and word != 386 and word != 858:
            sentence_lengths[ibatch] += 1
            word = np.random.zipf(alpha)
    return torch.tensor(sentence_lengths)


# Generate a batch of semi-realistic data using Zipf distribution for sentence lengths
# in the form of nested tensors with the jagged layout.
def gen_batch(N, E_q, E_k, E_v, device, dtype=torch.float32, query_seq_len_1=False):
    # generate semi-realistic data using Zipf distribution for sentence lengths
    sentence_lengths = zipf_sentence_lengths(alpha=1.2, batch_size=N)

    # Note: the torch.jagged layout is a nested tensor layout that supports a single ragged
    # dimension and works with torch.compile. The batch items each have shape (B, S*, D)
    # where B = batch size, S* = ragged sequence length, and D = embedding dimension.
    if query_seq_len_1:
        query = torch.nested.nested_tensor(
            [torch.randn(1, E_q, dtype=dtype, device=device) for l in sentence_lengths],
            layout=torch.jagged,
        )
    else:
        query = torch.nested.nested_tensor(
            [
                torch.randn(l.item(), E_q, dtype=dtype, device=device)
                for l in sentence_lengths
            ],
            layout=torch.jagged,
        )

    key = torch.nested.nested_tensor(
        [
            torch.randn(s.item(), E_k, dtype=dtype, device=device)
            for s in sentence_lengths
        ],
        layout=torch.jagged,
    )

    value = torch.nested.nested_tensor(
        [
            torch.randn(s.item(), E_v, dtype=dtype, device=device)
            for s in sentence_lengths
        ],
        layout=torch.jagged,
    )

    return query, key, value, sentence_lengths


import math
import timeit


def benchmark(func, *args, **kwargs):
    torch.cuda.synchronize()
    torch.cuda.reset_peak_memory_stats()
    begin = timeit.default_timer()
    output = func(*args, **kwargs)
    torch.cuda.synchronize()
    end = timeit.default_timer()
    return output, (end - begin), torch.cuda.max_memory_allocated()

现在我们将展示使用嵌套张量在 MultiheadAttention 层+编译进行自注意力时的性能提升。我们将此与传统 nn.MultiheadAttention +编译带有填充和掩码的方法进行比较。

一个基本的 GPT 风格 transformer 层由一个因果自注意力层和一个带有跳跃连接的前馈网络（FFN）组成。使用上面的 MultiheadAttention 层来实现这一点相当简单，并且与使用 nn.TransformerEncoderLayer 和 is_causal=True 得到的等效结果。

跨注意力

跨注意力是一种查询和键/值张量来自不同序列的注意力形式。

例如，在 nn.TransformerDecoderLayer 中，查询来自解码器，键/值来自编码器。

上述多头注意力层可以很好地推广到这种具有嵌套查询和键/值张量的情况。

完全遮蔽的行不再导致 NaN 值

nn.MultiheadAttention 和 scaled_dot_product_attention 存在一个长期存在的问题，如果一行被完全屏蔽，注意力层的输出将是 NaN。请参阅问题。这是因为对空集进行 softmax 是未定义的。

由于这个 PR，这种情况不再存在。相反， scaled_dot_product_attention 中对应完全遮挡行的输出将是 0。对于 nn.MHA 不采用“快速路径”的情况，这也适用。

在 nn.MultiheadAttention 中，强烈建议使用自定义 MHA 层与 NJT，因为 NJT 能够适当地建模不规则性，使得正确表达空序列成为可能。

FlexAttention + NJT

NJT 还可以与 FlexAttention 模块组合。这是对 MultiheadAttention 层的泛化，允许对注意力分数进行任意修改。下面的示例使用来自注意力健身房的 ALiBi 实现，并将其与嵌套输入张量一起使用。

from torch.nn.attention.flex_attention import flex_attention


def generate_alibi_bias(H: int):
    """Returns an alibi bias score_mod given the number of heads H
    Args:
        H: number of heads
    Returns:
        alibi_bias: alibi bias score_mod
    """

    def alibi_mod(score, b, h, q_idx, kv_idx):
        scale = torch.exp2(-((h + 1) * 8.0 / H))
        bias = (q_idx - kv_idx) * scale
        return score + bias

    return alibi_mod


query, key, value, _ = gen_batch(N, E_q, E_k, E_v, device)
n_heads, D = 8, E_q // 8
alibi_score_mod = generate_alibi_bias(n_heads)
query = query.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
key = key.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
value = value.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
out_flex2 = flex_attention(query, key, value, score_mod=alibi_score_mod)

此外，还可以通过 create_nested_block_mask 函数使用 FlexAttention 的 block_mask 工具与 NJT 结合。这有助于利用掩码的稀疏性来加速注意力计算。特别是，该函数为将 NJT 中所有可变长度序列组合成一个“堆叠序列”创建一个稀疏块掩码，同时正确屏蔽序列间的注意力。以下示例展示了如何使用此工具创建因果块掩码。

from torch.nn.attention.flex_attention import create_nested_block_mask


def causal_mask(b, h, q_idx, kv_idx):
    return q_idx >= kv_idx


query, key, value, _ = gen_batch(N, E_q, E_k, E_v, device)
block_mask = create_nested_block_mask(causal_mask, 1, 1, query, _compile=True)
query = query.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
key = key.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
value = value.unflatten(-1, [n_heads, D]).transpose(1, 2).detach().requires_grad_()
out_flex = flex_attention(query, key, value, block_mask=block_mask)

压缩投影

压缩投影是一种技术，它利用了投影输入（矩阵乘法）相同（自注意力）的事实，我们可以将投影权重和偏差打包到单个张量中。当单个投影受内存限制而不是计算限制时，特别有用。这里我们将演示两个示例：

  • MultiheadAttention 的输入投影

  • Transformer 层前馈网络中 SwiGLU 激活

MultiheadAttention 的输入投影

在进行自注意力时， query 、 key 和 value 是相同的张量。每个张量都通过一个 Linear(E_q, E_total) 层进行投影。相反，我们可以将其打包到一个层中，这就是我们在上面的 MultiheadAttention 层中所做的。

让我们比较打包投影与常规方法的性能：

class InputProjection(nn.Module):
    def __init__(self, E_q, E_total, bias=False, device=None, dtype=None):
        factory_kwargs = {"device": device, "dtype": dtype}
        super().__init__()
        self.q_proj = nn.Linear(E_q, E_total, bias=bias, **factory_kwargs)
        self.k_proj = nn.Linear(E_q, E_total, bias=bias, **factory_kwargs)
        self.v_proj = nn.Linear(E_q, E_total, bias=bias, **factory_kwargs)

    def forward(self, x):
        return self.q_proj(x), self.k_proj(x), self.v_proj(x)


class PackedInputProjection(nn.Module):
    def __init__(self, E_q, E_total, bias=False, device=None, dtype=None):
        factory_kwargs = {"device": device, "dtype": dtype}
        super().__init__()
        self.packed_proj = nn.Linear(E_q, E_total * 3, bias=bias, **factory_kwargs)

    def forward(self, query):
        return torch.chunk(self.packed_proj(query), 3, dim=-1)


B, D, dtype = 256, 8192, torch.bfloat16

torch.set_float32_matmul_precision("high")
in_proj = torch.compile(InputProjection(D, D, device="cuda", dtype=torch.bfloat16))
packed_in_proj = torch.compile(
    PackedInputProjection(D, D, device="cuda", dtype=torch.bfloat16)
)

q, _, _, sequence_lengths = gen_batch(B, D, D, D, device="cuda", dtype=torch.bfloat16)

# warmup
in_proj(q)
packed_in_proj(q)

# benchmark
(q_out, k_out, v_out), time, _ = benchmark(in_proj, q)
(q_out, k_out, v_out), time_packed, _ = benchmark(packed_in_proj, q)
# On my A100 prints 1.05x speedup
print(
    f"InputProjection: {time:5f} s, PackedInputProjection: {time_packed:5f} s, speedup: {time/time_packed:.2f}x"
)

Transformer 层 SwiGLU 前馈网络 ¶

Swish-Gated Linear Unit（SwiGLU）是一种在 Transformer 层（例如 Llama）的前馈网络中越来越受欢迎的非线性激活函数。具有 SwiGLU 激活的前馈网络定义为：

class SwiGLUFFN(nn.Module):
    def __init__(
        self,
        dim,
        hidden_dim,
        multiple_of,
        ffn_dim_multiplier=None,
        device=None,
        dtype=None,
    ):
        factory_kwargs = {"device": device, "dtype": dtype}
        super().__init__()
        hidden_dim = int(2 * hidden_dim / 3)
        # custom dim factor multiplier
        if ffn_dim_multiplier is not None:
            hidden_dim = int(ffn_dim_multiplier * hidden_dim)
        hidden_dim = multiple_of * ((hidden_dim + multiple_of - 1) // multiple_of)

        self.w1 = nn.Linear(dim, hidden_dim, bias=False, **factory_kwargs)
        self.w2 = nn.Linear(hidden_dim, dim, bias=False, **factory_kwargs)
        self.w3 = nn.Linear(dim, hidden_dim, bias=False, **factory_kwargs)

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

使用打包投影实现的另一种方法是

class PackedSwiGLUFFN(nn.Module):
    def __init__(
        self,
        dim,
        hidden_dim,
        multiple_of,
        ffn_dim_multiplier=None,
        device=None,
        dtype=None,
    ):
        factory_kwargs = {"device": device, "dtype": dtype}
        super().__init__()
        hidden_dim = int(2 * hidden_dim / 3)
        # custom dim factor multiplier
        if ffn_dim_multiplier is not None:
            hidden_dim = int(ffn_dim_multiplier * hidden_dim)
        hidden_dim = multiple_of * ((hidden_dim + multiple_of - 1) // multiple_of)

        self.w13 = nn.Linear(dim, 2 * hidden_dim, bias=False, **factory_kwargs)
        self.w2 = nn.Linear(hidden_dim, dim, bias=False, **factory_kwargs)

    def forward(self, x):
        x1, x3 = torch.chunk(self.w13(x), 2, dim=-1)
        return self.w2(F.silu(x1) * x3)

我们可以如下比较两种实现的性能。根据您的硬件，您可能会看到不同的结果。在 A100 上，我看到了 D=128 时的 1.12 倍速度提升。

    PackedSwiGLUFFN(D, D * 4, 256, device="cuda", dtype=torch.bfloat16)
)

q, _, _, sentence_lengths = gen_batch(D, D, D, D, device="cuda", dtype=torch.bfloat16)

    f"SwiGLUFFN: {time} s, PackedSwiGLUFFN: {time_packed} s, speedup: {time/time_packed:.2f}x"
)
