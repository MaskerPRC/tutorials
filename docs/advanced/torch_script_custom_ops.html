扩展 TorchScript 的自定义 C++运算符 ¶


创建时间：2025年4月1日 | 最后更新时间：2025年4月1日 | 最后验证时间：2024年11月5日

警告


本教程自 PyTorch 2.4 版本起已过时。请参阅 PyTorch 自定义运算符 以获取关于 PyTorch 自定义运算符的最新指南。


PyTorch 1.0 版本引入了 PyTorch 的一个新编程模型 PyTorch 脚本 . PyTorch 脚本是 Python 编程语言的一个子集，可以被 TorchScript 编译器解析、编译和优化。此外，编译后的 PyTorch 脚本模型可以选择序列化为磁盘文件格式，您可以从纯 C++（以及 Python）中加载和运行这些模型进行推理。


TorchScript 支持由 torch 提供的大量操作子集 包，允许您仅以纯文本形式表达许多种类的复杂模型 从 PyTorch 的“标准库”中的张量操作。尽管如此，可能 时代，你发现自己需要使用自定义扩展 TorchScript C++或 CUDA 函数。虽然我们建议您只有在必要时才选择此选项。 您的想法无法（足够高效地）用一个简单的 Python 函数表达 我们提供了一个非常友好且简单的界面来定义自定义的 C++和 CUDA 内核使用 ATen，PyTorch 的高性能 C++张量库。一旦绑定到 TorchScript，您可以将这些自定义内核（或“操作”）嵌入到您的 TorchScript 模型中，并在 Python 和 C++中直接以序列化形式执行。

以下段落提供了一个编写 TorchScript 自定义操作以调用 OpenCV 的示例，OpenCV 是一个用 C++编写的计算机视觉库。我们将讨论如何在 C++中处理张量，如何高效地将它们转换为第三方张量格式（在本例中为 OpenCV 的 Mat），如何将您的操作注册到 TorchScript 运行时，以及最后如何在 Python 和 C++中编译操作和使用它。

在 C++中实现自定义操作 ¶


对于这个教程，我们将展示 透视变换 函数，将图像应用透视变换，来自 OpenCV TorchScript 作为自定义操作符。第一步是编写自定义操作符的实现 让我们将自定义操作符的文件命名为 op.cpp，并使其看起来像这样： op.cpp

torch::Tensor warp_perspective(torch::Tensor image, torch::Tensor warp) {
  // BEGIN image_mat
  cv::Mat image_mat(/*rows=*/image.size(0),
                    /*cols=*/image.size(1),
                    /*type=*/CV_32FC1,
                    /*data=*/image.data_ptr<float>());
  // END image_mat

  // BEGIN warp_mat
  cv::Mat warp_mat(/*rows=*/warp.size(0),
                   /*cols=*/warp.size(1),
                   /*type=*/CV_32FC1,
                   /*data=*/warp.data_ptr<float>());
  // END warp_mat

  // BEGIN output_mat
  cv::Mat output_mat;
  cv::warpPerspective(image_mat, output_mat, warp_mat, /*dsize=*/{8, 8});
  // END output_mat

  // BEGIN output_tensor
  torch::Tensor output = torch::from_blob(output_mat.ptr<float>(), /*sizes=*/{8, 8});
  return output.clone();
  // END output_tensor
}


这个操作符的代码相当简短。在文件顶部，我们包含了 OpenCV 头文件，opencv2/opencv.hpp，以及 torch/script.h 头文件，它暴露了 PyTorch C++ API 中所有必要的功能，我们 需要编写自定义 TorchScript 操作符。我们的函数 warp_perspective 接受两个参数：一个输入 图像 和我们希望应用于图像的 仿射变换 矩阵。这些输入的类型是 torch::Tensor，这是 C++ 中 PyTorch 的张量类型（也是 Python 中所有张量的底层类型）。我们的 仿射变换 函数的返回类型也将是 torch::Tensor。

提示

有关 ATen 库的更多信息，请参阅 此说明 ，该库为 PyTorch 提供了 张量 类。此外， 本教程 描述了如何在 C++ 中分配和初始化新的张量对象（本操作不需要）。

注意


TorchScript 编译器理解固定数量的类型。只有这些类型 可以用作自定义运算符的参数。目前这些类型包括： torch::Tensor，torch::Scalar，double，int64_t 以及 std::vector 这些类型的序列。注意， 只有 double， 不是 float，以及只有 int64_t， 不是其他整数类型，例如 int，short 或 long 受支持。


在我们的函数内部，我们首先需要将 PyTorch 张量转换为 OpenCV 矩阵，因为 OpenCV 的 warpPerspective 期望 cv::Mat 以对象作为输入。幸运的是，有一种方法可以这样做 不复制 任何数据。在前几行，

  cv::Mat image_mat(/*rows=*/image.size(0),
                    /*cols=*/image.size(1),
                    /*type=*/CV_32FC1,
                    /*data=*/image.data_ptr<float>());


我们正在调用 这个构造函数 OpenCV Mat 类将我们的张量转换为 Mat 对象。我们传递给它原始图像张量的行数和列数、数据类型（在本例中我们将将其固定为 float32），以及最终指向底层数据的原始指针 – 一个 float*。这个 Mat 类构造函数的特殊之处在于它不会复制输入数据。相反，它将简单地引用这个内存以执行所有对 Mat 的操作。如果在 image_mat 上执行就地操作，这将反映在原始 image 张量中（反之亦然）。这使得我们可以在实际上存储数据在 PyTorch 张量的同时，调用后续的 OpenCV 程序，使用库的本地矩阵类型。 我们重复此过程将 扭曲 PyTorch 张量转换为 扭曲矩阵 OpenCV 矩阵：

  cv::Mat warp_mat(/*rows=*/warp.size(0),
                   /*cols=*/warp.size(1),
                   /*type=*/CV_32FC1,
                   /*data=*/warp.data_ptr<float>());


接下来，我们准备好调用我们迫切希望在 TorchScript 中使用 OpenCV 函数：warpPerspective。为此，我们将 OpenCV 函数传递给 image_mat 和 warp_mat 矩阵，以及一个名为 output_mat 的空输出矩阵。我们还指定了输出矩阵（图像）的大小 dsize，在这个例子中硬编码为 8 x 8。

  cv::Mat output_mat;
  cv::warpPerspective(image_mat, output_mat, warp_mat, /*dsize=*/{8, 8});


我们的自定义算子实现中的最后一步是将 将 output_mat 转换回 PyTorch 张量，以便我们可以在 PyTorch 中进一步使用它。这与我们之前进行的反向转换非常相似。在这种情况下，PyTorch 提供了一个 torch::from_blob 方法。 在这里，blob 指的是我们想要解释为 PyTorch 张量的某种不透明、扁平的内存指针。对 torch::from_blob 的调用如下所示：

  torch::Tensor output = torch::from_blob(output_mat.ptr<float>(), /*sizes=*/{8, 8});
  return output.clone();


我们使用 OpenCV Mat 类的 .ptr<float>() 方法来获取底层数据的原始指针（就像之前用于 PyTorch 张量的 .data_ptr<float>() 一样）。我们还指定了张量的输出形状，我们将其硬编码为 8 x 8。然后，torch::from_blob 的输出是一个 指向由 OpenCV 矩阵拥有的内存的 torch::Tensor。


在从我们的算子实现中返回这个张量之前，我们必须调用 .clone() 对张量进行，以执行底层数据的内存复制。这样做的原因是 torch::from_blob 返回的张量不拥有其数据。此时，数据仍然由 OpenCV 矩阵拥有。然而，这个 OpenCV 矩阵将在函数结束时超出作用域并被释放。如果我们直接返回 output 张量，那么当我们使用它时，它将指向无效的内存。调用 .clone() 返回一个新的张量，该张量拥有原始数据的副本，并且这个新的张量自己拥有这些数据。因此，可以安全地将其返回到外部世界。

在 TorchScript 中注册自定义算子 ¶

现在我们已经在 C++ 中实现了自定义操作符，我们需要将其 注册 到 TorchScript 运行时和编译器中。这将允许 TorchScript 编译器解析 TorchScript 代码中对我们的自定义操作符的引用。如果您曾经使用过 pybind11 库，我们的注册语法与 pybind11 语法非常相似。要注册单个函数，我们在 op.cpp 文件的顶层某处编写：

TORCH_LIBRARY(my_ops, m) {
  m.def("warp_perspective", warp_perspective);
}


在我们的 TORCH_LIBRARY 宏创建的函数将在程序启动时被调用。您的库名称 (my_ops) 作为第一个参数给出（不应加引号）。第二个参数 (m) 定义了一个类型为 torch::Library 是注册您操作符的主要接口。方法 Library::def 实际上创建了一个名为 warp_perspective 的操作符，将其暴露给 Python 和 TorchScript。您可以通过多次调用 def 来定义任意数量的操作符。

在幕后，def 函数实际上做了很多工作：它使用模板元编程来检查您函数的类型签名，并将其转换为操作符模式，该模式指定了在 TorchScript 类型系统中的操作符类型。

构建自定义操作符 ¶

现在我们已经在 C++中实现了自定义操作符并编写了其注册代码，现在是时候将其构建成一个（共享）库，以便我们可以将其加载到 Python 中进行研究和实验，或者在没有 Python 的环境中将其构建到 C++中进行推理。构建我们的操作符有多种方式，可以使用纯 CMake，或者 Python 替代方案，如 setuptools。为了简洁，下面的段落仅讨论 CMake 方法。本教程的附录深入探讨了其他替代方案。

环境设置 ¶

我们需要一个 PyTorch 和 OpenCV 的安装。最简单且最平台无关的方法是通过 Conda 来获取这两个库：

conda install -c pytorch pytorch
conda install opencv

使用 CMake 构建 ¶


要使用 CMake 构建系统将我们的自定义操作符构建到共享库中，我们需要编写一个简短的 CMakeLists.txt 文件，并将其与之前的 op.cpp 文件一起放置。为此，让我们约定一个如下所示的目录结构： 文件，并将其放置在我们的之前的 op.cpp 文件中。为此，让我们约定一个如下所示的目录结构：

warp-perspective/
  op.cpp
  CMakeLists.txt

我们 CMakeLists.txt 文件的内容应该是以下内容：

cmake_minimum_required(VERSION 3.1 FATAL_ERROR)
project(warp_perspective)

find_package(Torch REQUIRED)
find_package(OpenCV REQUIRED)

# Define our library target
add_library(warp_perspective SHARED op.cpp)
# Enable C++14
target_compile_features(warp_perspective PRIVATE cxx_std_14)
# Link against LibTorch
target_link_libraries(warp_perspective "${TORCH_LIBRARIES}")
# Link against OpenCV
target_link_libraries(warp_perspective opencv_core opencv_imgproc)

在 Python 中使用 TorchScript 自定义操作符 ¶

当我们的自定义操作符构建成共享库后，我们就可以在 Python 的 TorchScript 模型中使用这个操作符了。这分为两部分：首先将操作符加载到 Python 中，其次在 TorchScript 代码中使用操作符。


你已经看到了如何将你的操作符导入 Python： torch.ops.load_library() 这个函数接受包含自定义操作符的共享库的路径，并将其加载到当前进程中。加载共享库也将执行 TORCH_LIBRARY 块。这将注册我们的自定义操作符到 TorchScript 编译器，并允许我们在 TorchScript 代码中使用该操作符。


你可以用 torch.ops.<namespace>.<function> 来引用你加载的操作符，其中 <namespace> 是操作符名称的命名空间部分，并且 <function> 是操作符的函数名。对于我们上面编写的操作符，命名空间是 my_ops，函数名是 warp_perspective，这意味着我们的操作符作为 torch.ops.my_ops.warp_perspective 可用。虽然这个函数可以在脚本或跟踪的 TorchScript 模块中使用，但我们也可以在纯急切 PyTorch 中使用它并传递常规 PyTorch 张量：

import torch
torch.ops.load_library("build/libwarp_perspective.so")
print(torch.ops.my_ops.warp_perspective(torch.randn(32, 32), torch.rand(3, 3)))

备注


幕后发生的事情是，您第一次访问时 在 Python 中，TorchScript 编译器（在 C++领域）会检查是否已注册了一个函数 namespace::function，如果是，则返回一个 Python 句柄，我们可以随后使用这个句柄从 Python 调用我们的 C++操作符实现。这是 TorchScript 自定义操作符和 C++扩展之间一个值得注意的区别：C++扩展是使用 pybind11 手动绑定的，而 TorchScript 自定义操作符是由 PyTorch 本身动态绑定的。Pybind11 允许你绑定更多类型和类到 Python 中，因此对于纯急切代码推荐使用，但它不支持 TorchScript 操作符。


从现在起，您可以在脚本或跟踪代码中使用自定义操作符，就像使用来自 torch 包的其他函数一样。事实上，“标准库”函数如 torch.matmul 经历了大致相同的 注册路径作为自定义操作符，使自定义操作符真正 在如何以及在哪里使用方面是一等公民 TorchScript。然而，有一个区别是，标准库函数 有自定义的 Python 参数解析逻辑，这与 torch.ops 参数解析不同。

使用脚本中的自定义操作 ¶


除了追踪之外，将 PyTorch 程序转换为 TorchScript 表示的另一种方法是直接用 TorchScript 编写你的代码在 TorchScript 中。TorchScript 主要是对 Python 语言的子集，有一些限制使得它 更容易让 TorchScript 编译器理解程序。你可以免费将 常规 PyTorch 代码通过注解转换为 TorchScript，具体方法是 @torch.jit.script 用于免费函数，以及 @torch.jit.script_method 用于类中的方法（该类必须也继承自 torch.jit.ScriptModule）。更多关于 TorchScript 注解的详细信息，请参阅 这里 。

使用 TorchScript 而不是追踪的一个特定原因是，追踪无法捕获 PyTorch 代码中的控制流。因此，让我们考虑这个确实使用了控制流的函数：

要将此函数从纯 PyTorch 转换为 TorchScript，我们用 @torch.jit.script 进行注释：

def compute(x, y):

      z = 5
  else:

  return x.matmul(y) + z

使用 TorchScript 自定义操作符（C++）¶


TorchScript 的一个有用特性是将模型序列化为磁盘文件。此文件可以通过网络发送，存储在文件系统中，或者更重要的是，可以动态反序列化并执行，而无需保留原始源代码。这在 Python 中是可能的，同样在 C++中也是。为此，PyTorch 提供了一个纯 C++ API 用于反序列化和执行 TorchScript 模型。如果您还没有， 请阅读关于加载和运行序列化 TorchScript 模型的教程 在 C++ 中 ，接下来的几段将以此为基础。


简而言之，自定义运算符可以像常规 torch 运算符一样执行 即使是从文件反序列化并在 C++ 中运行也是如此。对此的唯一要求是 将我们之前构建的自定义运算符共享库链接到我们将要执行模型的 应用程序中。在 Python 中，这可以通过简单地调用 torch.ops.load_library. 在 C++ 中，您需要使用您所使用的任何构建系统将共享库链接到您的应用程序。以下示例将使用 CMake 展示这一点。

备注


从技术上讲，您也可以以与我们在 Python 中所做的方式类似的方式在运行时动态地将共享库加载到您的 C++ 应用程序中。 application at runtime in much the same way we did it in Python. On Linux, 您可以使用 dlopen 来完成此操作 . 其他平台也存在等效功能。

在上面链接的 C++执行教程的基础上，让我们从一个文件开始，创建一个最小的 C++应用程序，在另一个文件夹中，名为 main.cpp，从我们的自定义操作符中加载并执行一个序列化的 TorchScript 模型：

#include <torch/script.h> // One-stop header.

#include <iostream>
#include <memory>


int main(int argc, const char* argv[]) {
  if (argc != 2) {
    std::cerr << "usage: example-app <path-to-exported-script-module>\n";
    return -1;
  }

  // Deserialize the ScriptModule from a file using torch::jit::load().
  torch::jit::script::Module module = torch::jit::load(argv[1]);

  std::vector<torch::jit::IValue> inputs;
  inputs.push_back(torch::randn({4, 8}));
  inputs.push_back(torch::randn({8, 5}));

  torch::Tensor output = module.forward(std::move(inputs)).toTensor();

  std::cout << output << std::endl;
}

该节“构建自定义操作符”解释了如何使用 CMake 将自定义操作符构建到共享库中。本附录概述了两种进一步的编译方法。这两种方法都使用 Python 作为编译过程的“驱动程序”或“接口”。此外，它们都重新使用了现有的 基础设施 PyTorch 为 **C++ 扩展** 提供支持，这些扩展是 香草（急切）PyTorch 对 TorchScript 自定义操作符的等效实现 pybind11 用于将 C++ 中的函数“显式”绑定到 Python。


第一种方法使用 C++扩展的便捷的即时（JIT）编译接口 编译接口 首次运行 PyTorch 脚本时，在后台编译您的代码。 第二种方法依赖于久经考验的 setuptools 包，并涉及编写一个单独的 setup.py 文件。这允许更高级的配置以及与其他 setuptools-based 项目集成。以下将详细介绍这两种方法。

使用 JIT 编译构建 ¶

PyTorch C++ 扩展工具包提供的 JIT 编译功能允许将您的自定义操作符的编译直接嵌入到 Python 代码中，例如在训练脚本的顶部。

备注


“即时编译”在这里与在 TorchScript 编译器中进行的即时编译无关 这只是意味着您的自定义操作符 C++代码将在系统下的一个文件夹中编译，以优化您的程序。 第一次导入时，它将编译在您的系统目录 /tmp 下的一个文件夹中，就像您事先自己编译过一样。 /tmp 目录


这种即时编译功能有两种形式。在第一种中，你仍然将操作符实现保存在单独的文件中（op.cpp），然后使用 torch.utils.cpp_extension.load() 来编译你的扩展。通常，这个 函数将返回暴露你的 C++扩展的 Python 模块。然而， 由于我们不是将自定义操作符编译成自己的 Python 模块，所以我们 只想编译一个普通的共享库。幸运的是， torch.utils.cpp_extension.load() 有一个参数 is_python_module，我们可以将其设置为 False 来表示我们只对构建共享库感兴趣，而不是构建 Python 模块。 torch.utils.cpp_extension.load() 然后将编译并加载共享库到当前进程， 就像 torch.ops.load_library 之前所做的那样：

import torch.utils.cpp_extension

torch.utils.cpp_extension.load(
    name="warp_perspective",
    sources=["op.cpp"],
    extra_ldflags=["-lopencv_core", "-lopencv_imgproc"],
    is_python_module=False,
    verbose=True
)

print(torch.ops.my_ops.warp_perspective)

这应该大约打印：

<built-in method my_ops::warp_perspective of PyCapsule object at 0x7f3e0f840b10>


即时编译的第二种风味允许您传递您的源代码 自定义 TorchScript 操作符作为字符串。为此，使用 torch.utils.cpp_extension.load_inline :

import torch
import torch.utils.cpp_extension

op_source = """
#include <opencv2/opencv.hpp>
#include <torch/script.h>

torch::Tensor warp_perspective(torch::Tensor image, torch::Tensor warp) {
  cv::Mat image_mat(/*rows=*/image.size(0),
                    /*cols=*/image.size(1),
                    /*type=*/CV_32FC1,
                    /*data=*/image.data<float>());
  cv::Mat warp_mat(/*rows=*/warp.size(0),
                   /*cols=*/warp.size(1),
                   /*type=*/CV_32FC1,
                   /*data=*/warp.data<float>());

  cv::Mat output_mat;
  cv::warpPerspective(image_mat, output_mat, warp_mat, /*dsize=*/{64, 64});

  torch::Tensor output =
    torch::from_blob(output_mat.ptr<float>(), /*sizes=*/{64, 64});
  return output.clone();
}

TORCH_LIBRARY(my_ops, m) {
  m.def("warp_perspective", &warp_perspective);
}
"""

torch.utils.cpp_extension.load_inline(
    name="warp_perspective",
    cpp_sources=op_source,
    extra_ldflags=["-lopencv_core", "-lopencv_imgproc"],
    is_python_module=False,
    verbose=True,
)

print(torch.ops.my_ops.warp_perspective)


自然，最佳实践是仅使用 如果您的源代码相对较短，则应使用 torch.utils.cpp_extension.load_inline

注意，如果您在 Jupyter Notebook 中使用此功能，请不要多次执行带有注册的单元格，因为每次执行都会注册一个新的库并重新注册自定义操作符。如果需要重新执行，请先重启笔记本的 Python 内核。

使用 Setuptools 构建 ¶

第二种方法是从 Python 构建我们的自定义操作符是使用 setuptools。这有一个优点，即 setuptools 为用 C++编写的 Python 模块提供了一个非常强大和广泛的接口。然而，由于 setuptools 实际上是为构建 Python 模块而设计的，而不是普通的共享库（这些库没有 Python 从模块期望的必要入口点），这条路径可能会有点古怪。话虽如此，你只需要在 CMakeLists.txt 的位置放置一个 setup.py 文件，其外观如下：

from setuptools import setup
from torch.utils.cpp_extension import BuildExtension, CppExtension

setup(
    name="warp_perspective",
    ext_modules=[
        CppExtension(
            "warp_perspective",
            ["example_app/warp_perspective/op.cpp"],
            libraries=["opencv_core", "opencv_imgproc"],
        )
    ],
    cmdclass={"build_ext": BuildExtension.with_options(no_python_abi_suffix=True)},
)


请注意，我们已经启用了 no_python_abi_suffix 选项 在底部构建扩展。这指示 setuptools 忽略任何 Python-3 特定的 ABI 后缀在生成的共享库名称中。 否则，以 Python 3.7 为例，库可能被调用 warp_perspective.cpython-37m-x86_64-linux-gnu.so 其中 cpython-37m-x86_64-linux-gnu 是 ABI 标签，但我们实际上希望它被调用为 warp_perspective.so
