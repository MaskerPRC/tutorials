分析您的 PyTorch 模块 ¶


创建时间：2025年4月1日 | 最后更新时间：2025年4月1日 | 最后验证时间：2024年11月5日

作者：Suraj Subramanian

PyTorch 包含一个分析器 API，该 API 可用于识别代码中各种 PyTorch 操作的时间和内存成本。分析器可以轻松集成到您的代码中，并将结果打印为表格或以 JSON 跟踪文件的形式返回。

备注

分析器支持多线程模型。分析器在操作所在的线程中运行，但它也会分析可能运行在另一个线程中的子操作。并发运行的分析器将限定在其自己的线程中，以防止结果混合。

备注

PyTorch 1.8 引入了新的 API，该 API 将在未来的版本中替换旧的 API。请在新 API 页面此处查看。


转到这里 的食谱 为快速了解 Profiler API 的使用。

import torch
import numpy as np
from torch import nn
import torch.autograd.profiler as profiler

使用 Profiler 进行性能调试 ¶

Profiler 可以帮助您识别模型中的性能瓶颈。在此示例中，我们构建了一个自定义模块，该模块执行两个子任务：

  • 对输入进行线性变换，以及

  • 使用变换结果来获取掩码张量上的索引。


我们使用单独的标记上下文管理器将每个子任务的代码封装起来。 profiler.record_function("label") . 在分析器输出中，子任务中所有操作的聚合性能指标将显示在其对应的标签下。

注意，使用分析器会带来一些开销，最好只用于调查代码。记住，如果你正在基准测试运行时间，请将其移除。

class MyModule(nn.Module):
    def __init__(self, in_features: int, out_features: int, bias: bool = True):
        super(MyModule, self).__init__()
        self.linear = nn.Linear(in_features, out_features, bias)

    def forward(self, input, mask):
        with profiler.record_function("LINEAR PASS"):
            out = self.linear(input)

        with profiler.record_function("MASK INDICES"):
            threshold = out.sum(axis=1).mean().item()
            hi_idx = np.argwhere(mask.cpu().numpy() > threshold)
            hi_idx = torch.from_numpy(hi_idx).cuda()

        return out, hi_idx

配置前向传播 ¶

我们初始化随机输入和掩码张量，以及模型。


在运行分析器之前，我们预热 CUDA 以确保精确 性能基准测试。我们将模块的前向传播包装在 profiler.profile 上下文管理器。 with_stack=True 参数会将操作所在的文件和行号添加到跟踪中。

警告

with_stack=True 会产生额外的开销，更适合用于调查代码。记住，在基准测试性能时请移除它。

model = MyModule(500, 10).cuda()
input = torch.rand(128, 500).cuda()
mask = torch.rand((500, 500, 500), dtype=torch.double).cuda()

# warm-up
model(input, mask)

with profiler.profile(with_stack=True, profile_memory=True) as prof:
    out, idx = model(input, mask)

打印分析器结果 ¶


最后，我们打印分析器结果。 profiler.key_averages 按操作员名称汇总结果，并可按输入项进行汇总 形状和/或堆栈跟踪事件。 按输入形状进行分组有助于识别模型使用的张量形状 是由模型使用的。


在这里，我们使用 group_by_stack_n=5 来按操作及其回溯（截断到最近的 5 个事件）聚合运行时间，并按注册顺序显示事件。该表也可以通过传递一个 sort_by 参数进行排序（请参阅 文档 了解有效的排序键）。

备注


当在笔记本中运行分析器时，您可能会看到类似 <ipython-input-18-193a910735e8>(13): forward 的条目 而不是堆栈跟踪中的文件名。这些对应于 <notebook-cell>(line number): calling-function 。

print(prof.key_averages(group_by_stack_n=5).table(sort_by='self_cpu_time_total', row_limit=5))

提高时间性能 ¶


虽然消耗的时间也有所减少，但仍然过高。原来从 CUDA 到 CPU 复制矩阵的成本相当高！在 aten::copy_ 操作符在 forward (12) 中将 mask 复制到 CPU，以便使用 NumPy 的 argwhere 函数。aten::copy_ 在 forward(13) 将数组作为张量复制回 CUDA。如果我们使用，就可以消除这两个操作 torch 函数 nonzero() 这里。

class MyModule(nn.Module):
    def __init__(self, in_features: int, out_features: int, bias: bool = True):
        super(MyModule, self).__init__()
        self.linear = nn.Linear(in_features, out_features, bias)

    def forward(self, input, mask):
        with profiler.record_function("LINEAR PASS"):
            out = self.linear(input)

        with profiler.record_function("MASK INDICES"):
            threshold = out.sum(axis=1).mean()
            hi_idx = (mask > threshold).nonzero(as_tuple=True)

        return out, hi_idx

input = torch.rand(128, 500).cuda()
