使用 DDP 进行多 GPU 训练 ¶


创建时间：2025年4月1日 | 最后更新时间：2025年4月1日 | 最后验证：未验证

作者：Suraj Subramanian

你将学习到什么

  • 如何将单 GPU 训练脚本通过 DDP 迁移到多 GPU

  • 设置分布式进程组

  • 在分布式设置中保存和加载模型

在 GitHub 查看本教程中使用的代码

前提条件

  • DDP 工作原理的高级概述

  • 拥有多个 GPU 的机器（本教程使用 AWS p3.8xlarge 实例）

  • PyTorch 安装 配置 CUDA

按照下面的视频操作或访问 YouTube。

在上一教程中，我们得到了 DDP 工作原理的高级概述；现在我们来看看如何在代码中使用 DDP。在本教程中，我们从单个 GPU 的训练脚本开始，将其迁移到在单个节点上运行 4 个 GPU。在这个过程中，我们将讨论分布式训练中的重要概念，并在我们的代码中实现它们。

备注


如果您的模型包含任何 BatchNorm 层，则需要将其转换为 SyncBatchNorm 以同步跨副本的 BatchNorm 层的运行统计信息。 层。


使用辅助函数 使用 torch.nn.SyncBatchNorm.convert_sync_batchnorm(model) 函数将模型中的所有 BatchNorm 层转换为 SyncBatchNorm。

single_gpu.py 与 multigpu.py 的差异

这些是你通常对单 GPU 训练脚本进行的更改，以启用 DDP。

导入 ¶

  • torch.multiprocessing 是 PyTorch 对 Python 原生多进程的包装

  • 分布式进程组包含所有可以相互通信和同步的进程。

import torch
import torch.nn.functional as F
from utils import MyTrainDataset

import torch.multiprocessing as mp
from torch.utils.data.distributed import DistributedSampler
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.distributed import init_process_group, destroy_process_group
import os

构建进程组 ¶

  • 首先，在初始化进程组之前，调用 set_device，该函数为每个进程设置默认 GPU。这对于防止在 GPU:0 上出现挂起或过度内存使用非常重要


  • 进程组可以通过 TCP（默认）或共享文件系统进行初始化。更多关于 进程组初始化 的信息 初始化


  • init_process_group 初始化分布式进程组。


  • 了解更多关于选择 DDP 的信息。 后端

def ddp_setup(rank: int, world_size: int):
   """
   Args:
       rank: Unique identifier of each process
      world_size: Total number of processes
   """
   os.environ["MASTER_ADDR"] = "localhost"
   os.environ["MASTER_PORT"] = "12355"
   torch.cuda.set_device(rank)
   init_process_group(backend="nccl", rank=rank, world_size=world_size)

self.model = DDP(model, device_ids=[gpu_id])

  • 每个进程将接收一个包含 32 个样本的输入批次；有效的批次大小是 32 * nprocs，或者使用 4 个 GPU 时为 128。

train_data = torch.utils.data.DataLoader(

警告

集体调用是在所有分布式进程中运行的函数，它们用于将某些状态或值收集到特定进程中。集体调用要求所有排名都运行集体代码。在这个例子中，_save_checkpoint 不应该有任何集体调用，因为它只运行在 rank:0 进程中。如果您需要执行任何集体调用，它应该在 if self.gpu_id == 0 检查之前。
