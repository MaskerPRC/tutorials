通过示例学习混合前端语法 ¶


创建时间：2025 年 4 月 1 日 | 最后更新时间：2025 年 4 月 1 日 | 最后验证：未验证

作者：Nathan Inkawhich

本文旨在通过非代码密集型示例突出混合前端的语法。混合前端是 Pytorch 1.0 的一个新特性，为开发者提供了一个从 eager 模式过渡到图模式的途径。PyTorch 用户非常熟悉 eager 模式，因为它提供了我们作为研究人员所享受的易用性和灵活性。Caffe2 用户更熟悉图模式，它在 C++ 运行时环境中具有速度、优化机会和功能等优势。混合前端通过允许研究人员在 eager 模式（即 PyTorch）中开发和改进他们的模型，然后逐渐将经过验证的模型过渡到图模式以进行生产，当速度和资源消耗变得关键时，弥合了这两种模式之间的差距。

混合前端信息 ¶

模型转换为图模式的流程如下。首先，开发者以急切模式构建、训练和测试模型。然后，他们使用即时编译器（JIT）逐步追踪和脚本化模型的每个函数/模块，在每一步验证输出是否正确。最后，当顶级模型的所有组件都已追踪和脚本化后，模型本身被追踪。此时，模型已转换为图模式，并具有完整的无 Python 表示。使用这种表示，模型运行时可以利用高性能的 Caffe2 运算符和基于图的优化。

在我们继续之前，理解追踪和脚本的概念以及它们为何是分开的非常重要。追踪和脚本的目标是相同的，即创建给定函数中发生的操作的图表示。差异来自于急切模式的灵活性，它允许在模型架构中存在数据依赖的控制流。当一个函数没有数据依赖的控制流时，它可以使用 torch.jit.trace 进行追踪。然而，当一个函数有数据依赖的控制流时，它必须使用 torch.jit.script 进行脚本化。我们将混合前端的工作原理的细节留到另一份文档中，但下面的代码示例将展示如何追踪和脚本不同的纯 Python 函数和 torch 模块的语法。希望你会觉得使用混合前端是非侵入性的，因为它主要涉及向现有的函数和类定义中添加装饰器。

激励示例 ¶

在本例中，我们将实现一个奇特的数学函数，该函数可以逻辑上分为四个部分，其中包含和不包含数据依赖控制流。这里的目的是展示一个非代码密集型的示例，其中突出显示了即时编译（JIT）的使用。这个例子是一个有用模型的替代表示，其实施已被划分为各种纯 Python 函数和模块。

我们要实现的函数 \(Y(x)\) 定义为 \(x \epsilon \mathbb{N}\)。

\[z(x) = \Biggl \lfloor \frac{\sqrt{\prod_{i=1}^{|2 x|}i}}{5} \Biggr \rfloor\]
\[Y(x) = \begin{cases} \frac{z(x)}{2} & \text{if } z(x)\%2 == 0, \\ z(x) & \text{otherwise} \end{cases}\]
\[\begin{array}{| r | r |} \hline x &1 &2 &3 &4 &5 &6 &7 \\ \hline Y(x) &0 &0 &-5 &20 &190 &-4377 &-59051 \\ \hline \end{array}\]

如前所述，计算被分为四个部分。第一部分是简单的张量计算 \(|2x|\)，可以追踪。第二部分是迭代乘法计算，表示一个依赖于数据的控制流，其循环迭代次数在运行时取决于输入。第三部分是可追踪的 \(\lfloor \sqrt{a/5} \rfloor\) 计算。最后，第四部分处理 \(z(x)\) 的值所决定的输出情况，由于数据依赖性必须进行脚本化。现在，让我们看看它在代码中的样子。

第 1 部分 - 跟踪纯 Python 函数 ¶

我们可以将第一部分实现为一个纯 Python 函数，如下所示。注意，为了追踪此函数，我们调用 torch.jit.trace 并传入要追踪的函数。由于追踪需要提供预期运行时类型和大小的虚拟输入，我们还包括 torch.rand 以生成单个值的 torch 张量。

import torch

def fn(x):
    return torch.abs(2*x)

# This is how you define a traced function
# Pass in both the function to be traced and an example input to ``torch.jit.trace``
traced_fn = torch.jit.trace(fn, torch.rand(()))

第 2 部分 - 编写纯 Python 函数脚本 ¶

我们还可以将第二部分实现为一个纯 Python 函数，通过迭代计算乘积。由于迭代的次数取决于输入的值，因此我们有一个数据依赖的控制流，所以函数必须被脚本化。我们可以使用 @torch.jit.script 装饰器简单地脚本化 Python 函数。

# This is how you define a script function
# Apply this decorator directly to the function
@torch.jit.script
def script_fn(x):
    z = torch.ones([1], dtype=torch.int64)
    for i in range(int(x)):
        z = z * (i + 1)
    return z

第 3 部分 - 跟踪 nn.Module ¶

接下来，我们将在 torch.nn.Module 的 forward 函数中实现计算的第三部分。这个模块可以被跟踪，但不是在这里添加装饰器，而是在模块构建时处理跟踪。因此，类定义没有任何改变。

# This is a normal module that can be traced.
class TracedModule(torch.nn.Module):
    def forward(self, x):
        x = x.type(torch.float32)
        return torch.floor(torch.sqrt(x) / 5.)

第 4 部分 - 编写 nn.Module 脚本 ¶

在计算的最后一部分，我们有一个必须编写的 torch.nn.Module 。为了适应这一点，我们继承自 torch.jit.ScriptModule 并将 @torch.jit.script_method 装饰器添加到 forward 函数中。

# This is how you define a scripted module.
# The module should inherit from ScriptModule and the forward should have the
#   script_method decorator applied to it.
class ScriptModule(torch.jit.ScriptModule):
    @torch.jit.script_method
    def forward(self, x):
        r = -x
        if int(torch.fmod(x, 2.0)) == 0.0:
            r = x / 2.0
        return r

顶级模块

现在我们将通过一个名为 Net 的顶级模块将计算的各个部分组合起来。在构造函数中，我们将实例化 TracedModule 和 ScriptModule 作为属性。这是因为我们最终想要跟踪/编写顶级模块的脚本，而将跟踪/编写的模块作为属性可以允许 Net 继承所需的子模块的参数。请注意，这就是我们通过调用 torch.jit.trace() 并提供必要的虚拟输入来实际跟踪 TracedModule 的地方。同时请注意， ScriptModule 是按照常规方式构建的，因为我们已经在类定义中处理了脚本编写。

我们也可以打印出计算每个部分所创建的图表。打印出的图表使我们能够看到 JIT 最终如何将函数解释为图计算。

最后，我们为 Net 模块定义了 forward 函数，其中我们将输入数据 x 通过计算的四个部分。这里没有奇怪的语法，我们按预期调用跟踪和脚本化的模块和函数。

# This is a demonstration net that calls all of the different types of
# methods and functions
class Net(torch.nn.Module):
    def __init__(self):
        super(Net, self).__init__()
        # Modules must be attributes on the Module because if you want to trace
        # or script this Module, we must be able to inherit the submodules'
        # params.
        self.traced_module = torch.jit.trace(TracedModule(), torch.rand(()))
        self.script_module = ScriptModule()

        print('traced_fn graph', traced_fn.graph)
        print('script_fn graph', script_fn.graph)
        print('TracedModule graph', self.traced_module.__getattr__('forward').graph)
        print('ScriptModule graph', self.script_module.__getattr__('forward').graph)

    def forward(self, x):
        # Call a traced function
        x = traced_fn(x)

        # Call a script function
        x = script_fn(x)

        # Call a traced submodule
        x = self.traced_module(x)

        # Call a scripted submodule
        x = self.script_module(x)

        return x

运行模型

剩下的工作就是构建 Net 并通过前向函数计算输出。在这里，我们使用\(x=5\)作为测试输入值，并期望\(Y(x)=190\)。同时，也可以查看在构建 Net 过程中打印出的图表。

# Instantiate this net and run it
n = Net()
print(n(torch.tensor([5]))) # 190.

追踪顶级模型

示例的最后部分是追踪顶级模块， Net 。如前所述，由于追踪/脚本化的模块是 Net 的属性，因此我们可以追踪 Net ，因为它继承了追踪/脚本化子模块的参数。注意，追踪 Net 的语法与追踪 TracedModule 的语法相同。还可以查看创建的图。

n_traced = torch.jit.trace(n, torch.tensor([5]))
print(n_traced(torch.tensor([5])))
print('n_traced graph', n_traced.graph)

希望这份文档可以作为混合前端的入门介绍，以及为经验更丰富的用户提供的语法参考指南。同时，在使用混合前端时，还有一些需要注意的事项。追踪/脚本化方法必须编写在受限的 Python 子集内，因为不支持生成器、defs 和 Python 数据结构等特性。作为解决方案，脚本模型被设计成可以与追踪和非追踪代码一起工作，这意味着您可以从追踪函数中调用非追踪代码。然而，这种模型可能无法导出为 ONNX。
