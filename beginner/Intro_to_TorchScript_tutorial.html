TorchScript 不再处于活跃开发状态。

本教程是关于 TorchScript 的介绍，TorchScript 是 PyTorch 模型（nn.Module 的子类）的中间表示形式，可以在诸如 C++等高性能环境中运行。

  • 如何组合两种方法

import torch  # This is all you need to use both PyTorch and TorchScript!
print(torch.__version__)
torch.manual_seed(191009)  # set the seed for reproducibility

PyTorch 模型编写基础 ¶

让我们从定义一个简单的 模块 开始。在 PyTorch 中， 模块 是基本的组成单元。它包含：

  1. 构造函数，用于准备模块以供调用

  2. 一组 参数 和子 模块 。这些由构造函数初始化，并在模块调用期间可以使用。

  3. 一个 正向 函数。这是在模块被调用时运行的代码。

让我们来看一个小例子：

class MyCell(torch.nn.Module):
    def __init__(self):
        super(MyCell, self).__init__()

    def forward(self, x, h):
        new_h = torch.tanh(x + h)
        return new_h, new_h

my_cell = MyCell()
x = torch.rand(3, 4)
h = torch.rand(3, 4)
print(my_cell(x, h))

我们已经：

  1. 创建了一个继承自 torch.nn.Module 的类。

  2. 定义了一个构造函数。构造函数并没有做太多，只是调用了 super 的构造函数。


  3. 定义了一个 forward 函数，该函数接收两个输入并返回两个输出。实际上 forward 函数的内容并不重要，但它是某种意义上的假 RNN cell–即–它是一个在循环中应用的功能。


我们实例化了模块，并创建了 x 和 h，它们只是 3x4 的 随机值矩阵。然后我们调用了 cell，使用 my_cell(x, h)。这反过来又调用了我们的 forward 函数。

让我们来做点更有趣的事情：

class MyCell(torch.nn.Module):
    def __init__(self):
        super(MyCell, self).__init__()
        self.linear = torch.nn.Linear(4, 4)

    def forward(self, x, h):
        new_h = torch.tanh(self.linear(x) + h)
        return new_h, new_h

my_cell = MyCell()
print(my_cell)
print(my_cell(x, h))


我们重新定义了我们的模块 MyCell，但这次我们添加了一个 self.linear 属性，并在 forward 函数中调用了 self.linear。

这里到底发生了什么？ torch.nn.Linear 是 PyTorch 标准库中的一个 Module。就像 MyCell 一样，它可以使用 call 语法来调用。我们正在构建一个 Module 的层次结构。


print 在一个 模块 上将给出一个可视化的表示。 模块 的子类层次结构。在我们的例子中，我们可以看到我们的 线性 子类及其参数。 通过这种方式组合 模块 ，我们可以简洁且易于阅读地编写具有可重用组件的模型。

通过这种方式组合 模块 ，我们可以简洁且易于阅读地编写具有可重用组件的模型。


你可能已经注意到了输出中的 grad_fn。这是 PyTorch 自动微分方法的细节。 PyTorch 的自动微分方法，称为 autograd。简而言之，这个系统允许我们通过可能复杂的程序计算导数。这种设计使得在模型编写方面具有巨大的灵活性。

现在我们来考察这种灵活性：

class MyDecisionGate(torch.nn.Module):
    def forward(self, x):
        if x.sum() > 0:
            return x
        else:
            return -x

class MyCell(torch.nn.Module):
    def __init__(self):
        super(MyCell, self).__init__()
        self.dg = MyDecisionGate()
        self.linear = torch.nn.Linear(4, 4)

    def forward(self, x, h):
        new_h = torch.tanh(self.dg(self.linear(x)) + h)
        return new_h, new_h

my_cell = MyCell()
print(my_cell)
print(my_cell(x, h))


我们再次重新定义了我们的 MyCell 类，但在这里我们进行了定义 MyDecisionGate。此模块利用了 控制流 。控制流包括循环和 if-语句。

许多框架采用给定完整程序表示来计算符号导数的方法。然而，在 PyTorch 中，我们使用梯度带。我们记录操作的发生，并在计算导数时反向回放它们。这样，框架无需显式地为语言中的所有构造定义导数。

TorchScript 基础 ¶

现在，让我们看看我们的运行示例，看看我们如何应用 TorchScript。

简而言之，TorchScript 提供了工具来捕获您模型的定义，即使在 PyTorch 灵活和动态的特性下也是如此。让我们首先来了解一下我们所说的 跟踪 。

跟踪 模块 ¶

class MyCell(torch.nn.Module):
    def __init__(self):
        super(MyCell, self).__init__()
        self.linear = torch.nn.Linear(4, 4)

    def forward(self, x, h):
        new_h = torch.tanh(self.linear(x) + h)
        return new_h, new_h

my_cell = MyCell()
x, h = torch.rand(3, 4), torch.rand(3, 4)
traced_cell = torch.jit.trace(my_cell, (x, h))
print(traced_cell)
traced_cell(x, h)


我们稍微回放了，取了我们的第二个版本 MyCell 如前所述，我们实例化了它，但这次我们调用了 torch.jit.trace，传入了一个 Module，以及网络可能看到的 示例 输入

这究竟做了什么？它调用了 模块 ，记录了当 模块 运行时发生的操作，并创建了一个 torch.jit.ScriptModule 实例（TracedModule 是其一个实例）

TorchScript 将其定义记录在中间表示（或 IR），在深度学习中通常被称为 图 。我们可以使用 .graph 属性来检查这个图：

print(traced_cell.graph)

然而，这是一个非常底层的表示，图中包含的大部分信息对最终用户来说并不有用。相反，我们可以使用 .code 属性来给出代码的 Python 语法解释：

print(traced_cell.code)

那么 为什么 我们要这样做？有几个原因：

  1. TorchScript 代码可以在自己的解释器中调用，这实际上是一个受限的 Python 解释器。这个解释器不会获取全局解释器锁，因此可以在同一实例上同时处理许多请求。

  2. 此格式允许我们将整个模型保存到磁盘，并在另一个环境中加载，例如在用非 Python 语言编写的服务器中。

  3. TorchScript 为我们提供了一个表示，我们可以对代码进行编译器优化，以提供更高效的执行。

  4. TorchScript 允许我们与许多后端/设备运行时进行接口，这些运行时需要比单个操作符更广泛的程序视图。

我们可以看到调用 traced_cell 产生的结果与 Python 模块相同：

print(my_cell(x, h))
print(traced_cell(x, h))

使用脚本转换模块 ¶

我们使用模块的第二个版本而不是带有控制流子模块的版本，这是有原因的。现在让我们来分析一下：

class MyDecisionGate(torch.nn.Module):
    def forward(self, x):
        if x.sum() > 0:
            return x
        else:
            return -x

class MyCell(torch.nn.Module):
    def __init__(self, dg):
        super(MyCell, self).__init__()
        self.dg = dg
        self.linear = torch.nn.Linear(4, 4)

    def forward(self, x, h):
        new_h = torch.tanh(self.dg(self.linear(x)) + h)
        return new_h, new_h

my_cell = MyCell(MyDecisionGate())
traced_cell = torch.jit.trace(my_cell, (x, h))

print(traced_cell.dg.code)
print(traced_cell.code)


查看代码 .code 的输出，我们可以看到 if-else 分支根本不存在！为什么？追踪器正是我们所说的那样：运行代码，记录发生的操作 发生 并构建 脚本模块能精确地做到这一点。不幸的是，像控制流这样的内容会被删除。


我们如何忠实地在 TorchScript 中表示这个模块呢？我们提供了一个 脚本编译器 ，它直接分析您的 Python 源代码，将其转换为 TorchScript。让我们使用脚本编译器将 MyDecisionGate 转换：

scripted_gate = torch.jit.script(MyDecisionGate())

my_cell = MyCell(scripted_gate)
scripted_cell = torch.jit.script(my_cell)

print(scripted_gate.code)
print(scripted_cell.code)

哈喽！我们现在已经忠实地捕捉了程序在 TorchScript 中的行为。现在让我们尝试运行这个程序吧：

# New inputs
x, h = torch.rand(3, 4), torch.rand(3, 4)
print(scripted_cell(x, h))

混合脚本和追踪 ¶

有些情况下，我们更倾向于使用追踪而不是脚本（例如，一个模块有许多基于常量 Python 值的架构决策，我们希望这些值不出现在 TorchScript 中）。在这种情况下，脚本可以与追踪结合使用：torch.jit.script 将内联追踪模块的代码，而追踪将内联脚本模块的代码。

第一种情况的一个例子：

class MyRNNLoop(torch.nn.Module):
    def __init__(self):
        super(MyRNNLoop, self).__init__()
        self.cell = torch.jit.trace(MyCell(scripted_gate), (x, h))

    def forward(self, xs):
        h, y = torch.zeros(3, 4), torch.zeros(3, 4)
        for i in range(xs.size(0)):
            y, h = self.cell(xs[i], h)
        return y, h

rnn_loop = torch.jit.script(MyRNNLoop())
print(rnn_loop.code)

第二种情况的例子：

class WrapRNN(torch.nn.Module):
    def __init__(self):
        super(WrapRNN, self).__init__()
        self.loop = torch.jit.script(MyRNNLoop())

    def forward(self, xs):
        y, h = self.loop(xs)
        return torch.relu(y)

traced = torch.jit.trace(WrapRNN(), (torch.rand(10, 3, 4)))
print(traced.code)

当需要使用脚本和跟踪时，可以使用这种方式，并且可以将它们一起使用。

保存和加载模型 ¶

我们提供 API 来将 TorchScript 模块保存到/从磁盘的归档格式中。此格式包括代码、参数、属性和调试信息，这意味着归档是模型的独立表示，可以在完全不同的进程中加载。让我们保存和加载我们的包装 RNN 模块：

traced.save('wrapped_rnn.pt')

loaded = torch.jit.load('wrapped_rnn.pt')

print(loaded)
print(loaded.code)


如您所见，序列化保留了我们在整个过程中检查的模块层次和代码。该模型也可以加载，例如， 导入 C++ 以进行无 Python 执行。
