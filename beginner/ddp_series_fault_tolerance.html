具有容错能力的分布式训练与 torchrun¶


创建时间：2025年4月1日 | 最后更新时间：2025年4月1日 | 最后验证时间：2024年11月5日

作者：Suraj Subramanian

你将学习到什么

  • 使用 torchrun 启动多 GPU 训练作业

  • 保存和加载您的训练作业快照

  • 为优雅重启结构化您的训练脚本

在 GitHub 查看本教程中使用的代码

前提条件

  • DDP 的高级概述

  • 熟悉 DDP 代码

  • 拥有多个 GPU 的机器（本教程使用 AWS p3.8xlarge 实例）

  • PyTorch 安装 配置 CUDA

按照下面的视频操作或访问 YouTube。

在分布式训练中，单个进程的故障可能会中断整个训练任务。由于这里的故障可能性更高，因此使您的训练脚本健壮尤为重要。您可能还希望您的训练任务能够 弹性 ，例如，计算资源可以在任务过程中动态加入或离开。

PyTorch 提供了一个名为 torchrun 的实用工具，它提供了容错和弹性训练功能。当发生故障时，torchrun 会记录错误并尝试从训练作业的最后一个保存的“快照”自动重启所有进程。

快照不仅保存模型状态，还可以包括运行过的 epoch 数量、优化器状态或训练作业的任何其他状态属性，这些属性对于其连续性是必要的。

为什么使用 torchrun¶

torchrun 处理分布式训练的细节，这样您就无需自己处理。例如，

  • 您无需设置环境变量或显式传递 rank 和 world_size；torchrun 会分配这些以及其他几个 环境变量 。

  • 您无需在脚本中调用 mp.spawn；您只需要一个通用的 main() 入口点，并使用 torchrun 启动脚本。这样，相同的脚本可以在非分布式、单节点和多节点设置中运行。

  • 从上次保存的训练快照中优雅地重启训练。

优雅重启 ¶

为了优雅的重启，你应该这样结构化你的训练脚本：

def main():
  load_snapshot(snapshot_path)
  initialize()
  train()

def train():
  for batch in iter(dataset):
    train_step(batch)

    if should_checkpoint:
      save_snapshot(snapshot_path)

如果发生故障，torchrun 将终止所有进程并重新启动它们。每个进程的入口点首先加载并初始化最后一个保存的快照，然后从那里继续训练。因此，在任何故障发生时，你只会丢失从最后一个保存的快照以来的训练进度。

在弹性训练中，每当有任何成员变更（添加或删除节点）时，torchrun 将终止并在可用的设备上启动进程。这种结构确保了你的训练作业可以在无需人工干预的情况下继续。

保存和加载快照 ¶

定期将所有相关信息存储在快照中，使我们的训练任务在中断后能够无缝恢复。

+ def _save_snapshot(self, epoch):
+     snapshot = {}
+     snapshot["MODEL_STATE"] = self.model.module.state_dict()
+     snapshot["EPOCHS_RUN"] = epoch
+     torch.save(snapshot, "snapshot.pt")
+     print(f"Epoch {epoch} | Training snapshot saved at snapshot.pt")

+ def _load_snapshot(self, snapshot_path):
+     snapshot = torch.load(snapshot_path)
+     self.model.load_state_dict(snapshot["MODEL_STATE"])
+     self.epochs_run = snapshot["EPOCHS_RUN"]
+     print(f"Resuming training from snapshot at Epoch {self.epochs_run}")

恢复训练 ¶

训练可以从上次运行的最后一个 epoch 继续，而不是从头开始。

def train(self, max_epochs: int):
-  for epoch in range(max_epochs):
+  for epoch in range(self.epochs_run, max_epochs):
      self._run_epoch(epoch)
